================================================================================
                              DATA FLOW EXAMPLES
================================================================================

1. RESTAURANT OVERVIEW FLOW
   ┌────────────┐      GET /newcms/restaurant/overview      ┌────────────┐
   │   Client   │─────────────────────────────────────────▶ │   FastAPI  │
   └────────────┘                 (JWT token)               └──────┬─────┘
                                                                   │
                                                                   │ SQL queries
                                                                   ▼
   ┌────────────┐      {metrics, plat_costs, ...}          ┌────────────┐
   │  Dashboard │◀─────────────────────────────────────────│ PostgreSQL │
   └────────────┘           JSON response                   └────────────┘


2. MOBILE SCAN FLOW
   ┌────────────┐      POST /newcms/mobile/scan            ┌────────────┐
   │   Mobile   │─────────────────────────────────────────▶│   FastAPI  │
   │    App     │  {"code_barre": "3245678901234"}         └──────┬─────┘
   └────────────┘                                                  │
                                                                   │ SELECT ... WHERE code_barre = ?
                                                                   │ (10-30ms with index)
                                                                   ▼
   ┌────────────┐      {found: true, product: {...}}       ┌────────────┐
   │   Scan UI  │◀─────────────────────────────────────────│ PostgreSQL │
   └────────────┘           JSON response                   └────────────┘


3. STOCK ADJUSTMENT FLOW
   ┌────────────┐      POST /newcms/mobile/adjust          ┌────────────┐
   │   Mobile   │─────────────────────────────────────────▶│   FastAPI  │
   │    App     │  {product_id: 1, adjustment: -1,         └──────┬─────┘
   └────────────┘   reason: "breakage"}                           │
                                                                   │ BEGIN TRANSACTION
                                                                   │ SELECT ... FOR UPDATE
                                                                   │ UPDATE ingredients SET stock = ...
                                                                   │ INSERT mouvements_stock (audit)
                                                                   │ COMMIT
                                                                   ▼
   ┌────────────┐      {old_stock: 15.5, new_stock: 14.5}  ┌────────────┐
   │   Success  │◀─────────────────────────────────────────│ PostgreSQL │
   │   Screen   │           JSON response                   └────────────┘
   └────────────┘


================================================================================
                              PERFORMANCE METRICS
================================================================================

Endpoint                    Avg Time    Optimization
────────────────────────────────────────────────────────────────────────────
/restaurant/overview        200-500ms   • SQL aggregation
                                        • Cache recommended (5min TTL)

/mobile/inventory           50-100ms    • LIMIT/OFFSET pagination
                                        • Index on tenant_id

/mobile/scan                10-30ms     • Index on code_barre (CRITICAL)
                                        • Single row lookup

/mobile/adjust              50-100ms    • Transaction atomicity
                                        • FOR UPDATE lock


================================================================================
                                 SECURITY
================================================================================

Authentication:   JWT token via get_current_tenant
Authorization:    tenant_id isolation on all queries
Validation:       Pydantic schemas (strict types)
SQL Injection:    Parameterized queries (SQLAlchemy)
Concurrency:      FOR UPDATE lock on stock adjustments
Audit Trail:      All adjustments logged in mouvements_stock
